# JMeter Report to PNG

Given a JMeter HTML dashboard report, this skill extracts the data behind each
card and re-renders it as a PNG: tables are drawn on a canvas, and charts are
rendered with Chart.js (`chartjs-node-canvas`). PNGs are written to the
workspace root unless the user asks for another folder.

## Inputs

- The report folder generated by `jmeter -g results.jtl -o <dir>` or
  `jmeter -n -t plan.jmx -l results.jtl -e -o <dir>`, or that folder's
  `index.html`.
- Which cards to capture. If the user did not say, ask them in Phase 2.
- Optional: an output folder.

If the user only has a `.jtl` results file and JMeter is installed, generate the
report first with `jmeter -g <file>.jtl -o <dir>`. Ask before installing JMeter.

## Where the data lives

A JMeter dashboard is a folder, not a single HTML file. `index.html` holds empty
placeholders; the data is JSON embedded in the report's JavaScript:

| Card | Source |
|---|---|
| Test and Report information | `index.html`, `#generalInfos` table |
| Requests Summary (pie) | `content/js/dashboard.js`, `var data = {"OkPercent": …, "KoPercent": …}` |
| APDEX, Statistics, Errors, Top 5 Errors by sampler | `content/js/dashboard.js`, `createTable($("#<id>"), {titles, overall, items}, …)` |
| Graphs (over time, percentiles, distributions, TPS, …) | `content/js/graph.js`, `var <name>Infos = { data: {"result": {series, title, granularity, …}} }` |

Graph series are `[[x, y], …]`; over-time graphs use epoch-millisecond `x`
values. The script reads these JSON literals directly and never executes the
report's JavaScript.

`references/sample-report/` is a complete, unmodified JMeter 5.6.3 report; open
its `index.html` in a browser to compare against the PNGs. Use it to see the
exact format or to test the script:
`node <skill-dir>/scripts/render-cards.mjs <skill-dir>/references/sample-report --list`.

To regenerate it (requires JMeter, e.g. `brew install jmeter`), create a synthetic
results file and let JMeter build the report from it, then replace
`references/sample-report/` with the generated folder:

```sh
node <skill-dir>/scripts/generate-sample-jtl.mjs /tmp/results.jtl
jmeter -g /tmp/results.jtl -o /tmp/report
```

## Phase 1 — Prepare

1. Resolve the report folder. Confirm `content/js/dashboard.js` exists; if it
   does not, the input is not a JMeter dashboard report — tell the user and stop.
2. Install the renderer dependencies once (skill-local, not in the user's
   project):

   ```sh
   npm install --prefix <skill-dir>/scripts
   ```

## Phase 2 — Choose the cards

1. List the cards available in this report (graphs with no data are omitted):

   ```sh
   node <skill-dir>/scripts/render-cards.mjs <report-dir> --list
   ```

2. If the user named specific cards, map them to the listed names (for example
   "response time chart" → `response-times-over-time`). If a name matches more
   than one card (e.g. "latency" → `latencies-over-time`, `latencies-vs-request`),
   or none, ask which they meant.
3. Otherwise, do not render everything. Ask the user to pick the cards they
   want from the listed names as a multi-select question (use the ask-questions
   tool if available), with a readable label for each (e.g.
   `response-times-over-time` → "Response Times Over Time"). Preselect nothing,
   and include an "All cards" option. Wait for the answer before rendering.
4. Pass exactly the chosen cards to `--only`. Omit `--only` only when the user
   chose "All cards".

## Phase 3 — Render

Run from the workspace root so PNGs land there by default:

```sh
node <skill-dir>/scripts/render-cards.mjs <report-dir> [--only statistics,errors,response-times-over-time] [--out <dir>]
```

Each card is written as `jmeter-<card>.png`, and the script prints each path.
Existing files with the same name are overwritten.

## Phase 4 — Verify and report

1. Open one table PNG and one chart PNG to check they rendered (non-blank,
   labels legible).
2. Spot-check a value, e.g. the Statistics `Total` row `#Samples` and `Error %`
   against the report.
3. Report the files written as a short list, plus any requested card that was
   missing from the report.

## Notes

- Tables use the dashboard's own formatting: Apdex to 3 decimals, thresholds as
  durations, error percentages with `%`, response times to 2 decimals. Long
  error messages are truncated with `…`.
- Time axes match the dashboard, not the viewer. When JMeter builds the report
  it bakes in the generating machine's UTC offset
  (`fixTimeStamps(infos.data.result.series, 28800000)` in `graph.js` is
  UTC+08:00) and the dashboard displays those shifted timestamps as UTC. The
  script reads the same offset, so tick times equal the dashboard's, and adds
  it to the x-axis label (e.g. "Elapsed Time (granularity: 1 min, UTC+08:00)").
  If a report has no offset, the script uses the local time zone of the machine
  running it.
- Chart axis labels (horizontal and vertical) are read from each graph's
  options in `graph.js`, so they match the dashboard (e.g. "Average response
  time in ms").
- If `npm install` fails building `canvas`, the platform lacks prebuilt
  binaries; see the `canvas` package README for the system libraries to
  install, and tell the user rather than retrying.
